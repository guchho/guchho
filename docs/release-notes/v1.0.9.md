# Guchho 1.0.9

**Released 2026-10-26.**

## Added

### `guchho lint` - a standalone linter

`guchho lint` checks JavaScript and TypeScript without producing a build. Run it
with no paths to lint every supported source file under the working directory,
or name the files to check:

```bash
guchho lint
guchho lint src
guchho lint --rule no-console:error --rule no-unused-vars:warning
```

The command has its own configuration file - `guchho.lint.config.js`, `.mjs`,
`.cjs` or `.json`, found by searching upward from the working directory - with
`include`/`exclude` patterns, `extends`, globals, a platform (`browser`, `node`
or `neutral`), and per-rule levels. Configuration is validated: unknown fields
and invalid values are reported rather than ignored.

Fifteen rules ship with the linter, including `no-undef`, `no-unused-vars`,
`no-redeclare`, `no-unreachable`, `no-duplicate-imports`, `valid-typeof`,
`eqeqeq` and `import/no-unresolved`. Two have safe fixes: `eqeqeq` (only where
the rewrite cannot change coercion) and `no-debugger`.

- **Fixing**: `--fix` writes safe fixes, `--fix-dry-run` reports them without
  writing, and `--watch` re-runs when sources or configuration change.
- **Output**: `--format=human|stylish|json` (or `--json`), with `--quiet` to
  hide warning blocks. Human output keeps the source line, caret range and
  location; JSON output carries per-file messages, a flat message list and
  counts.
- **Exit codes**: `1` for a lint error or for warnings above
  `--max-warnings`, `2` for a usage or configuration failure, and `130` when
  interrupted in watch mode.

The optional checks that run during a build are separate, configured through
`build.lint`; see [`guchho lint`](../reference/cli/lint.md) and the
[build options](../reference/config/build.md#optional-lint-checks).

### `lint()` in the `guchho` package

`lint(options)` runs the same rule set and safe fixes as the command and answers
with the findings as data rather than a terminal report:

```js
import { lint } from "guchho";

const result = await lint({
  files: ["src/app.js"],
  rules: { "no-console": "off" },
  maxWarnings: 0,
});

console.log(`${result.errorCount} errors, ${result.warningCount} warnings`);
```

A lint error is a result, not a rejected promise. `fix` and `fixDryRun` behave
as their flags do, and `maxWarnings` sets the threshold reported by
`maxWarningsExceeded`. In the browser, `lint()` works when the lint config is
JSON; a JavaScript config is native-only because evaluating it needs a child
process the WebAssembly engine does not have. See the
[`lint()` API](../api/README.md#lint).

### Optional lint checks during a build

Beyond the standalone command, a build can run parser-level checks on
JavaScript. They are off by default and are enabled through `build.lint`:

```json
{ "build": { "lint": { "undefined": "error", "unused": "warning" } } }
```

`undefined` reports references with no visible binding, `unused` reports
unreferenced locals and parameters, and `unused-variable` and
`unused-parameter` split that check. `true` enables every check at `warning`;
a string or array enables just the named checks. Findings can be silenced or
promoted through the existing `log_override` mechanism. Analysis is
platform-aware and stays silent in `with` scopes and in files containing direct
`eval`.

### `guchho unpack` and `unpack()`

`guchho unpack` extracts zip, tar and tar.gz archives. The format comes from the
extension first and from magic bytes when the name gives nothing away.

```bash
guchho unpack dist.zip
guchho unpack release.tar.gz -o out/
guchho unpack bundle.zip --strip-components=1
```

`--outdir`, `--format`, `--overwrite` and `--strip-components` control where
and how files land. Absolute paths and `..` components are refused, so an
archive cannot write outside the destination, and symlinks and other special
entries are skipped with a warning. Tar headers are checksum-verified and PAX
records are honoured; gzip streams are checked against their CRC-32 and length
trailer. Permissions and modification times are restored where the host file
system supports them.

The same operation is available as `unpack()` in the `guchho` package, with the
same defaults and safety rules. It is native-only: the browser entry exports the
name and throws, because the WebAssembly engine has no host file system. See
[`guchho unpack`](../reference/cli/unpack.md) and the
[`unpack()` API](../api/README.md#unpack).

## Improved

### JavaScript syntax diagnostics

Misspelled keywords and missing closing delimiters now carry a structured
suggestion alongside the existing message text, so an editor or tool can offer
the correction without parsing the human-readable string. The fallback message
text is unchanged, so existing log filters and snapshots keep working.

## Platform

Android builds now target API level 24 (Android 7.0) and link the C++ runtime
statically. The dev server needs `getifaddrs()`, which Android grew in API 24,
and a `c++_shared` binary would fail to start on a device that does not have the
NDK runtime library beside it. Binaries for Android therefore require Android
7.0 or newer.

## Upgrading

Nothing here is breaking for users of 1.0.8. Upgrade to pick up the linter,
archive extraction and the improved diagnostics:

```bash
npm install -g guchho@1.0.9
npm install -D @guchho/wasm@1.0.9
```
